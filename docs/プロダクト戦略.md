# 煙道 ENDO — プロダクト戦略（現在の仮説と検討事項）

> 「同じものを、みんなで何度も擦る」という中心思想と、そこから派生する**現在の仮説**をまとめる。
> ルール本体（毎回効かせる判断基準）は `CLAUDE.md`。ここはその背景と、まだ決まっていないことの置き場。
> ⚠️ **ここに書かれた「仮説・検討中」は実装ルールとして固定しない。** 決定事項と混同しないこと。
> 最終更新: 2026-08-15

---

## 0. 中心思想（確定）

煙道の価値は「誰か一人が考えた美味しいレシピを載せること」ではない。
**同じフレーバー・同じMIXを、多くの人が何度も作り、吸い、評価し、再現し、その結果を蓄積すること**にある。

そこから「本当に再現される作り方 / 実際に支持される作り方 / 経験に裏付けられた作り方」を見つけ、
最終的に「日本のシーシャの"王道"を、みんなでつくる」へつなげる。

したがって **method の投稿数そのものより、実証データの方が重要**：
実際に作られた回数 / 作った人数 / リピート回数 / 再現された回数 / 評価 / Original と Reproduction の比較 / 作り手の経験量。

**煙道は「シーシャ版クックパッド」にしない。** 無数のレシピを投稿して終わりにせず、同じ対象を擦り続ける。

蓄積する価値は「レシピそのもの」ではなく、**実証データ**：
何人が作ったか / 何回作ったか / 誰が作ったか / 何度リピートしたか / どんな結果になったか / 他者が再現できたか / Original と Reproduction がどれくらい近かったか。

## 1. 有力な方向性：テーマ固定型（仮説）

当初は「誰でも自由に投稿する UGC 型」を中心に考えていた。
現在は **「大量投稿そのもの」を価値にせず、「同じフレーバー・同じMIXを何度も擦り、最適解を探すこと」を中心に置く**方向で検討している。

煙道側がテーマとなるフレーバー/MIX を指定し、
**「このフレーバーを、みんなはどう作るのか？」** を集中的に検証するモデルが有力。

### 第一弾は MIX である必要がない
重要な仮説：**第一弾は MIX でなくてよい。**

例）「Al Fakher Double Apple 100%」を固定し、**フレーバーそのものを変数から外す**。
その上で、作り方そのものを比較・検証する：

ボウル / 詰め方 / HMD / 炭 / 炭数 / 炭配置 / 初期加熱 / 熱管理 / 時間経過 / 吸い方 / 調整方法

これは「同じものを擦って最適解を探す」という思想を、最も純粋な形で実現できる可能性がある。

### 第一テーマ候補：Al Fakher Double Apple
理由は「世界的に非常に有名で、シーシャにおける代表的なフレーバーの一つ」であること。
将来のグローバル展開時に、**世界中の作り手が知っている可能性が高い同一フレーバー**を軸にできる意味は大きい。

重要なのは「世界中で完全に同一条件になる」ことではない。
むしろ **「同じフレーバーを、それぞれの地域・店舗・作り手がどう作るのか」を比較できること**に価値がある。

## 2. 「一番美味しい」の扱い（仮説）

「誰が一番美味しく作れるか？」は、ユーザー参加を促すコピーとしては有効な可能性がある。

ただし **「美味しい」は主観**なので、単純な数値だけで「絶対的な世界一の作り方」を決定することは避ける。

目指すのは「誰が勝ったか」ではなく、
**「どの作り方が、どれだけ実際に作られ、再現され、支持されているか」** を明らかにすること。

評価に使う候補：総合評価 / 味覚5軸 / 作成回数 / 再現回数 / リピート回数 / 再現者数 / 第三者比較。

---

## 3. プロと一般ユーザーの違い＝経験量（仮説）

最大の違いは肩書きではなく **経験量・試行回数**。

シーシャは一台を作ると通常2〜3時間据えるため、一般ユーザーが一日に大量の試行を行うことは難しい。
一方シーシャ店舗では日常的に大量に作るため、**同じフレーバーを何度も作る**ことができる。
店舗・プロは「**圧倒的な試行回数を生み出せる存在**」として重要。

ただし **「プロだから正しい」「店舗だから信用できる」という思想ではない。**
店舗の強みは権威ではなく「大量の試行・経験を持つ可能性が高いこと」にある。

### 経験量をデータとして扱う
「Double Apple を12回作ったユーザー」と「1,000回作った店舗スタッフ」では、そのフレーバーの経験量が大きく違う。
この差を肩書きで表現せず、**煙道上の実績データとして記録する**ことを検討する。

候補：特定フレーバーの作成回数 / 特定 method の作成回数 / リピート回数 / method 投稿数 / 満足評価 / 他者による再現回数 / 他者による評価数。

狙いは「プロだから信頼できる」ではなく、
**「この人は実際にこのフレーバーを何百回も作っている」** という形で信頼性を構築すること。

### 店舗の役割
店舗は「正しい答えを持っている存在」ではなく、**「大量の試行を生み出せる場所」** として重要。
一店舗で同じ Double Apple を毎日複数台作り、少しずつ変えながら検証できる。この試行回数そのものが価値あるデータ。

将来的に「店舗の経験量 / 特定フレーバーの作成回数 / method の反復回数」の可視化を検討する。

### プロ限定にはしない方向を有力視
投稿者をプロ限定にすることは**確定しない**。
一般ユーザーを広く受け入れ、その中にプロ・店舗が参加してくる構造の方が「みんなで王道をつくる」と整合する可能性がある。

プロは「プロだから投稿できる」のではなく、
**「経験量・試行回数・再現実績によって自然に存在感が高まる」** 構造が望ましい。

一般ユーザーも 作る / 吸う / 評価する / 再現する / リピートする ことで煙道のデータを育てられる。

## 4. 再現性の検証（仮説）

### 「作った」という記録の限界
「作った」という自己申告だけでは、完全な信頼性は担保できない。
「再現成功」という評価も人によって基準が異なるため、単純な Yes/No では再現性の証明にならない。

**「作った」は重要な行動データとして扱うが、それだけで「この method は再現性がある」と断定しない。**
（この一文はルールとして `CLAUDE.md` の設計原則にも置いている）

### Original / Reproduction / Third Party Comparison
| 概念 | 内容 |
|---|---|
| **Original** | method を投稿した本人が、その method に従って作った一台 |
| **Reproduction** | 別のユーザーが method を見て実際に作った一台 |
| **Third Party Comparison** | Original と Reproduction の**両方を実際に吸った第三者**が、類似度・違いを評価する |

「再現した本人が美味しいと思った」だけでは「元の method が再現された」とは断定しない。
より強い再現性評価が必要な場面では、両方を体験した第三者の比較データを利用する構造を検討する。

### 二段階構造（第三者比較は通常フローにしない）
全 method に第三者比較を課すとユーザー負担が大きすぎる。

- **通常** … 作った / 吸った / 評価した / 何回作った / リピートした などの軽いデータを大量に蓄積
- **王道候補** … 特に有力な method にのみ、Original / Reproduction / Third Party Comparison の厳密な検証を行う

### リピート再現を重要データとする
「一回だけ美味しく作れた」より、**「何度も同じ作り方で作って、安定して結果を出せる」** ことを重視する。

重要データ：同じ method を何回作ったか / 何人が作ったか / 同じ人が繰り返し作ったか / 繰り返しの評価はどうだったか。

例）method A＝1回作成、method B＝50回作成 なら、B の方に多くの実証データが存在する。
この「リピート再現」は「同じフレーバーを擦って最適解を見つける」という中心思想そのもの。

## 5. 王道の成立条件（思想・確定）

王道は「人気ランキング」でも「いいね数」でも「投稿数」だけでもない。

**作られ・吸われ・再現され・リピートされ・必要に応じて第三者比較された**データが蓄積された method を、
煙道が確認・認定して「王道」が成立する。

**現時点で王道0件でも問題ない。** データがまだ存在しない段階だからである。

---

## 6. グローバル展開（仮説）

煙道のモデルは日本限定ではなく、世界展開できる可能性がある。

「世界的に普及している代表的なフレーバーを一つテーマに設定し、世界中の作り手がそのフレーバーをどう作るのかを比較する」モデルを検討する。

第一弾候補：**Al Fakher Double Apple**

「誰が一番美味しく作るか」を競うことだけを目的にせず、
**「世界中の作り手が、どのように作り、どの method が再現され、どの method が支持されるのか」** をデータ化する。
地域ごとの作り方の違いも価値になる。

将来的に Japan / US / Europe / Middle East / Global などの比較が可能になる可能性がある。

## 7. 有料化（判断済み・保留）

直近では課金・有料コンテンツを**採用しない**。
以前検討していた「プロの詳細な作り方を有料販売する」モデルは現時点で保留。

まず優先するのは、データネットワークの構築：
ユーザー数 / 作成数 / 再現数 / リピート数 / 評価データ / method 数 / 王道候補。

課金は **「煙道にしか存在しない十分な価値・データが蓄積された後」** に再検討する。

## 10. 旧方針との関係（要判断・未解決）

`docs/ローンチ戦略.md` は **「初期150 method を幅広く揃えて、検索したときに空にならないようにする」**（＝**広さ優先**）を前提にしている。

一方、本ドキュメントの「テーマ固定型」は **「1テーマを深く擦る」**（＝**深さ優先**）であり、**方向が競合する**。

現時点でどちらも上書き・破棄していない。
**どちらを採るか、あるいは併存させるか（例：テーマ1本＋最低限の図鑑）は未決定**であり、
**初期データ投入の作業に入る前に決める必要がある。**

判断材料：
- 広さ優先 … 検索が空にならない。図鑑としての体裁が整う。ただし1 combo あたりの method が薄く、王道比較が成立しにくい
- 深さ優先 … 中心思想を最も純粋に体現できる。ただし「図鑑」としては空に見える期間が長くなる
