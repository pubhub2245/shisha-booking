## 1. 自己ループ修正

**原因**：mix 詳細の「この組み合わせの作り方をすべて見る」が、method 1件でも常に `/combo/…` へ送っていました。combo 側は method が1件だと mix へ redirect するため、**同じ mix 詳細に戻る自己ループ**になっていました。

**修正**：`getComboBySlug` で同一 `combo_key` の公開 method 数を取得し、件数で出し分け。

| 条件 | 挙動 |
|---|---|
| method 1件 | **リンクを表示しない** |
| method 2件以上 | 「**ほかの作り方を見る（N）**」を表示（N＝表示中を除いた別解の数） |

combo ページ自体は削除していません。

## 8. 認証UX調査結果（今回は実装せず・提案のみ）

**現在の設定**
- Supabase Auth のメール／パスワード認証
- `lib/site.ts` の **`EMAIL_ENABLED` フラグが false** の運用
- そのため signup 時に「⚠️ メール認証を使わない運用のため、パスワードを忘れると再設定できません」と警告を表示
- `/forgot`・`/reset-password` の**画面と server action は実装済み**（`requestPasswordReset` / `updatePassword`）だが、`EMAIL_ENABLED` が false のためログイン画面から導線が出ていない

**A. password reset を有効にする場合の変更量：小**
1. Supabase ダッシュボードで SMTP を設定（既定の制限付き送信でも可）
2. Redirect URLs に本番の `/auth/callback`・`/reset-password` を登録
3. `EMAIL_ENABLED` を true にする
→ **コード変更はフラグ1つ**。画面もアクションも既にあります。

**B. magic link を併用する場合の変更量：中**
1. 上記1〜2に加えて `signInWithOtp` を使う新しいアクション
2. ログインフォームに「メールでログイン」導線とメール送信後の状態表示
3. `/auth/callback` の分岐確認
→ 新規コードが必要（フォーム＋アクション＋状態遷移）。

**推奨：A（password reset を有効化）**
理由：既に実装が揃っておりフラグ1つで有効化でき、既存ユーザーのログイン方法を変えないため。magic link は「パスワード管理をなくす」効果はありますが、今の課題（再設定できない）はAで解消します。

**production で最低限直すべき点**：SMTP を設定して `EMAIL_ENABLED=true` にすること。現状は**パスワードを忘れたユーザーが復旧できない**状態で、公開前に解消しておくべきです。警告文の言い換えだけで隠す対応はしていません。

## 10. 余白の原因（調査結果・意図された余白）

**原因**：sticky footer パターンです。

```html
<body class="flex min-h-dvh flex-col pb-16 md:pb-0">
  <main class="flex-1">…</main>
  <SiteFooter />
</body>
```
＋ `globals.css` の `body { min-height: 100dvh }`

- `main` の `flex-1` により、コンテンツが短いとき main が伸びてフッターが画面下に固定されます
- モバイルの `pb-16` は**下部固定ナビの逃げ**（`md:pb-0` でデスクトップは0）

**バグではありません。** 条件付きセクション（おすすめ・写真・今作れる王道・combos）はすべて `length > 0` でガードされており、**空のセクションが枠だけ描画される問題は見つかりませんでした**。

現在データが8ミックスと少なくセクションが出ないため main が短くなり、余白が目立って見えています。**コンテンツが増えれば自然に解消**するため、§11 の方針どおり詰めていません。
