# A. 完全なユーザージャーニー

各段階を「見るもの / 考えること / 選択 / 入力 / 表示 / 次の行動 / なぜ次をしたくなるか」で記述する。
登場人物は2人。**佐藤（既存の自作勢・器材あり）** と **鈴木（初心者・器材は最低限）**。

## PHASE 0 — 流入と最初の理解

### 【0-1】トップページ（通常の煙道）

**見るもの**
通常の煙道。図鑑・検索・保存・最近の記録。その中に**1ブロックだけ**特別エリア。

```
┌────────────────────────────────┐
│  今月の煙道検証                              │
│                                              │
│  AL FAKHER  ダブルアップル                   │
│  この一台の、最適解を探す。                  │
│                                              │
│  検証対象 10 ／ 作った人 32 ／ 比較中 14      │
│                            [ 見てみる → ]    │
└────────────────────────────────┘
```

**考えること**
- 佐藤:「ダブルアップル？ 普通すぎない？ ……でも10通りもあるのか」
- 鈴木:「シーシャの作り方って人によって違うんだ」

**選択** 見てみる／無視してトップを回遊する（**無視できることが重要**。テーマは強制ではない）

**なぜ次に進むか**
「ダブルアップル」ではなく **「10通りの作り方がある」** が引っかかる。
フレーバーへの興味ではなく、**差異への興味**が動機。

> **設計上の要点**：ここで「Double Apple の研究をしています」と書かない。
> 新規ユーザーには意味が伝わらない。伝えるのは「同じフレーバーでも作り方で変わる」という事実。

## PHASE 1 — 1台目（基準点をつくる）

### 【1-1】基準 METHOD 選択（3問）

METHOD 一覧から自力で選ばせない。**3問だけ聞いて、1件に絞り込む。**

```
あなたのいつもの作り方を教えてください
（あとから変えられます）

Q1. ボウルは？
    [ クレイ ] [ ファンネル ] [ ハリカ/ボルテックス ]
    [ シリコン ] [ わからない・持っていない ]

Q2. 熱の管理は？
    [ HMD（ロータス等） ] [ アルミ箔で直火 ] [ わからない ]

Q3. 炭はいくつ？
    [ 2個 ] [ 3個 ] [ 4個以上 ] [ わからない ]
```

**入力** 3タップ。自由入力なし。「わからない」を必ず用意する（鈴木のため）。

**表示（回答後）**

```
あなたに一番近いのは、この作り方です

  #03  ファンネル / ふんわり / ロータス / 炭3個 / 蒸らし7分
       作った人 8 ／ 2回以上作った人 3

  あなたの回答との違い：詰め方だけ未確認

        [ この作り方で1台つくる ]
        [ ほかの候補も見る（2件） ]
```

- 佐藤（3問すべて回答）→ 最も近い1件＋代替2件
- 鈴木（すべて「わからない」）→ **標準的で器材要求が最も少ない1件**を提示
  （コピーは「一番近い」ではなく **「はじめての1台におすすめ」**）

**なぜ次に進むか**
選択肢が10件から**1件**になり、しかも「自分に近い」理由が明示されている。
決定コストがほぼ消える。

> **設計上の要点**：3問の回答は**この場の絞り込みにのみ使い、保存しない**（保存はDB変更になる）。
> 基準点は「実際に作った1台目の METHOD」で表現できるため、保存は不要。

### 【1-4】記録

**タイミング**：吸い終わった後。作った直後ではない。

**入力（3ステップ・すべて任意で止められる）**

```
① [ この作り方で作った ]              ← 1タップで記録完了

② どうだった？（任意）
   [ また吸いたい ] [ おいしかった ] [ ふつう ] [ 好みではなかった ]

③ 味の印象（任意・分かるものだけ）
   甘さ    1 2 3 4 5
   清涼感  1 2 3 4 5
   酸味    1 2 3 4 5
   濃厚さ  1 2 3 4 5
   重さ    1 2 3 4 5
```

> **重要な前提**：③がなければ「あなたの中の比較」は成立しない。
> ただし**必須にはしない**。代わりに③の直前で理由を1行で伝える：
> **「次の1台と比べるために、覚えているうちに残しておくと後で効きます」**
>
> ※ 現在「作った」ボタンには②③が付いていない（§17 で詳述）。**第一テーマの前提条件**。

### 【1-5】★1台目 完了画面 — 最重要画面その1

```
──────────────────────────────
  記録しました。あなたは #03 の 9人目 です。

  ▼ 全体の中でのあなた
     甘さ   あなた 3 ／ この作り方の平均 3.4（評価5人）
     重さ   あなた 4 ／ この作り方の平均 3.8
     ※評価者が3人未満の作り方では平均を出しません

──────────────────────────────
  ★ もう1台作ると、あなたの中の比較が出ます

     いま出せるのは「他の人と比べてどうか」だけです。
     同じテーマでもう1つ作ると、
     「あなたの舌で、どちらが甘かったか」が分かります。
──────────────────────────────

  ▼ 次の1台

     #07
     あなたが作った #03 と、違うのは1つだけ。

        炭の数    3個 → 2個
        （ボウル・詰め方・HMD・蒸らしは同じ）

     炭を1つ減らすと、あなたにはどう変わるのか。

           [ #07 を見る ]   [ あとで ]

  ▼ ほかの候補（2件）／ 検証対象は残り9件

  ─────────────────────────
  この記録は煙道帳に残りました。次の1台もそこから戻れます。
──────────────────────────────
```

**考えること**「炭1個減らすだけなら今すぐできる。しかも自分の中で比較が出るのか」

**なぜ次に進むか（この画面が第一テーマの成否を決める）**
1. **未完了感**：「あなたの中の比較」がまだ出ていないと明示される
2. **具体性**：「おすすめ」ではなく **「炭の数だけが違う」**
3. **実行コストゼロ**：炭を1個減らすだけ。買い物が発生しない
4. **知的好奇心**：自分で確かめられる問いの形になっている

> **設計上の要点**：ここで投稿を勧めない。保存も勧めない。**次の1台だけを出す。**

## PHASE 2 — 2台目（比較が生まれる）

### 【2-1】METHOD 詳細（2台目）

1台目と違い、**冒頭が差分**になる。

```
#07

  ▼ あなたが作った #03 との違い     ← 最上部・第一級情報
     炭の数   3個 → 2個
     ほかは同じ（ファンネル / ふんわり / ロータス / 蒸らし7分）

  ▼ この作り方の要点
     ……
```

### 【2-2】作る → 記録（1台目と同じ）

味の入力の直前のコピーが変わる：
**「#03 のときは 甘さ3 でした。今回はどうでしたか？」**
→ 前回値を見せることで、入力の動機と精度が同時に上がる。

### 【2-3】★2台目 完了画面 — 最重要画面その2

```
──────────────────────────────
  ★ あなたの中の比較ができました

              #03（炭3個）    #07（炭2個）
     甘さ          3      →      4
     重さ          4      →      3
     濃厚さ        4      →      4
     判定    おいしかった  →  また吸いたい

     あなたは、炭を1つ減らした #07 の方を
     「甘く・軽く」感じました。

     ※これはあなた1人の1回の比較です。
       ほかの人が同じように感じるとは限りません。
──────────────────────────────
  ▼ 全体の中でのあなた
     あなたは #07 の 12人目。
     甘さ  あなた 4 ／ 平均 3.9（評価6人）
     → 全体の感じ方と近いです
──────────────────────────────
  ▼ 次の1台

     #11
     いま試した #07 と、違うのは1つだけ。
        詰め方   ふんわり → ぎっしり

     熱を変えたら甘くなった。では詰め方を変えたら？

           [ #11 を見る ]   [ あとで ]

  検証対象は残り8件 ／ あなたが試したのは2件
──────────────────────────────
```

**なぜ3台目に進むか**
1台目→2台目で**実際に差が出た**という成功体験が確定した。
「熱を変えたら変わった。では詰め方は？」という**自分の問い**が生まれている。
ここから先はサービスに促されなくても進む。

> **表現の厳密さ（重要）**：
> ✅「あなたは #07 の方を甘く感じました」＝ 事実の記述
> ❌「#07 の方が甘いです」＝ 一般化。n=1 でこれを言わない
> 王道を人気投票化しないのと同じ原則を、個人の比較にも適用する。

## PHASE 4 — 投稿（強制しない）

### 【4-1】投稿を提案するタイミング

以下のいずれかを満たしたときのみ、**1回だけ**提案する。

| 条件 | 提案文 |
|---|---|
| 3台以上作り、どれとも違う自分のやり方がある | 「あなたのやり方は、検証対象のどれとも違うようです。登録しますか？」 |
| 【1-1】の3問の回答が、どの検証対象とも2軸以上違った | 「あなたの作り方は、まだ誰も登録していない組み合わせです」 |
| 自分の記録に**リピート**がある（同じ作り方を2回以上） | 「繰り返し作っているやり方があります。これは他の人の役に立ちます」 |

**1台目・2台目の完了画面では絶対に投稿を勧めない。** 比較体験の途中で目的をすり替えない。

### 【4-2】投稿画面

既存の `/post`（かんたん／詳しく）をそのまま使う。
ただしテーマから来た場合のみ：
- フレーバーは AL FAKHER ダブルアップル で**固定済み**
- 5軸（ボウル/詰め方/HMD/炭の数/初期加熱）を**先頭**に置く
- 「あなたが作った #03 との違い」をプレビュー表示 → **投稿前に自分の独自性を確認できる**

### 【4-3】投稿後

```
  登録しました。

  あなたの作り方は、#03 と「詰め方」「炭の数」が違います。
  検証対象に加えるかは煙道が判断します（数日いただきます）。

  ▼ あなたの作り方が試されると、ここに再現者が表示されます
     まだ0人
```

**検証対象への採用は自動にしない。** 運営が選ぶ（M3 の集中を守るため）。
ただし**投稿自体は誰でもでき、テーマ内に表示される**（自由投稿は閉じない）。

## PHASE 5 — 蓄積の先（8週間の外）

```
  検証者が増える → 各 METHOD の再現者が増える
    → 味覚評価が3人以上ついた METHOD が増える
      → リピートが発生した METHOD が現れる
        → 王道候補（門の通過）
          → 煙道が確認して認定 → combo_orthodoxy に1件
```

**ここは8週の必達目標にしない。** 到達したら「強い成功」。

# B. 画面構成

**新規に作る画面は1つだけ。** 残りは既存画面の拡張か、既存画面内のセクション。

| # | 画面 | 種別 | 実体 |
|---|---|---|---|
| 1 | トップのテーマ入口 | 既存画面に**1ブロック追加** | `app/page.tsx` |
| 2 | テーマページ | **既存画面の拡張** | `app/combo/[slug]/page.tsx` |
| 3 | 基準 METHOD 選択（3問） | **テーマページ内のステップ**（独立画面にしない） | 同上 |
| 4 | METHOD 詳細 | **既存画面の拡張**（差分ブロックを最上部に） | `app/mix/[id]/page.tsx` |
| 5 | 記録（作った→判定→味覚） | **既存コンポーネントの拡張** | `MadeButton` |
| 6 | **記録後の発見** | **新規（唯一）** | 1台目/2台目/3台目以降で内容が変わる同一画面 |
| 7 | 自分の比較履歴 | **煙道帳内のテーマセクション** | `app/mypage/page.tsx` + `EndoLog` |
| 8 | METHOD 投稿 | 既存 | `app/post/page.tsx` |

### 意図的に「作らない」画面

| 作らないもの | 理由 |
|---|---|
| METHOD 一覧（独立画面） | テーマページの下部で足りる。一覧を主役にすると「選べない」が起きる |
| 2台目推薦（独立画面） | 【1-5】完了画面に統合。画面を分けると離脱点が1つ増える |
| 「次に試す METHOD」（独立画面） | 完了画面と煙道帳の2箇所に置けば十分 |
| METHOD 比較（独立画面） | 差分は METHOD 詳細の最上部と完了画面に出す。専用画面は行動を生まない |
| テーマ用ランキング | **作らない**（人気ランキング化を避ける・§11 の思想） |
| 器材登録画面 | 第一テーマでは検証対象の選定基準で代替（§17 参照） |

# C. 各画面の情報優先順位

原則：**「何が違うのか」を第一級情報にする。人気・評価は第二級に落とす。**

### 1. トップのテーマ入口
1. 何を検証しているか（フレーバー名＋一文）
2. 検証対象の件数 ／ 2つ以上作った人の数
3. 入口ボタン
- ❌ 出さない：ランキング、いいね数

### 2. テーマページ
1. 問い（なぜ100%なのか）
2. **主導線「基準の1台を選ぶ」**
3. 熱カーブ比較（差が視覚で分かる）
4. 参加状況（検証対象数／作った人／2つ以上作った人）
5. 検証対象一覧（スクロール下部）
- ❌ 出さない：人気順ソート、いいね数の大きい表示

### 3. METHOD 詳細
1. **要点5軸**（ボウル/詰め方/HMD/炭/蒸らし）
2. **あなたが作った METHOD との差分**（2台目以降は最上部）
3. 実績（作った人／2回以上作った人／味の評価者数）
4. 作り手の経験量
5. 手順の詳細
6. 主アクション「この作り方で作った」
- ❌ 出さない：いいね数を上位に置くこと

### 4. 記録
1. 作った（1タップ）
2. どうだった？（4択・任意）
3. 味の印象（5軸・任意）＋ **前回値の表示**

### 5. 記録後の発見（内容が段階で変わる）
| 段階 | 1位 | 2位 | 3位 |
|---|---|---|---|
| 1台目 | 何人目か | **「もう1台で比較が出ます」予告** | 次の1台（差分1軸） |
| 2台目 | **あなたの中の比較** | 全体の中での位置 | 次の1台 |
| 3台目〜 | あなたの中の比較 | **あなたの傾向（断定しない）** | 次の1台／未踏の METHOD |

### 6. 煙道帳（テーマセクション）
1. あなたがテーマで作った METHOD 一覧と味覚の推移
2. **次の1台**（完了画面を離れても戻れる）
3. 検証対象の消化状況（10件中◯件）

# E. 「次の1台」をどう決めるか（人間が読めるルール）

まだアルゴリズムを実装しない。**運営が手で選んでも同じ結果になるルール**として定義する。

## 必須条件（すべて満たすものだけが候補）

1. **検証対象 METHOD である**（自由投稿は推薦しない）
2. **そのユーザーがまだ作っていない**
3. **基準 METHOD との差分が 1〜2軸**（3軸以上は候補から外す）
4. **追加の器材購入が要らない**（基準 METHOD と同じ器材で作れる）

## 優先順位（上から順に適用）

| 順 | 条件 | 理由 |
|---|---|---|
| 1 | **差分が1軸だけ** | 原因が特定でき、学びが確実に発生する |
| 2 | **その1軸が「変更コスト0」の軸** | 下表の通り。買い物が発生した瞬間に離脱する |
| 3 | **再現者が少ない METHOD** | データの穴を埋める（運営側の都合。ユーザーには見せない） |
| 4 | **味の差が出やすいと期待される軸** | 初回で「変わった」を体験させる（仮説・§19参照） |

## 差分軸の「変更コスト」階層 ★実務上いちばん効く

| 軸 | 変更コスト | 2台目に適するか |
|---|---|---|
| **炭の数** | 0（今ある炭の数を変えるだけ） | ◎ 最優先 |
| **初期加熱（蒸らし）** | 0（時間を変えるだけ） | ◎ |
| **詰め方** | 0（技術だけ） | ○ |
| HMD | 高（購入が必要な場合がある） | △ 3台目以降 |
| ボウル | 高（購入が必要な場合がある） | △ 3台目以降 |

→ **2台目は必ず「炭の数」か「初期加熱」から出す。** これで障壁「器材が違って作れない」を実装ゼロで回避する。

## 除外ルール

- 自分が投稿した METHOD は「次の1台」に出さない（他人の METHOD を試すことが目的）
- 「あとで」を2回押された METHOD は、しばらく出さない
- 検証対象を全部作り終えたら、**まだ誰も試していない自由投稿の METHOD**へ切り替える

## 提示件数

**1件。** 代替候補は畳んで2件まで。3件以上並べた時点で「選べない」が再発する。

# F. 1台目→2台目の動線（最重要）

第一テーマの成否はここに集中する。Primary KPI がまさにこの遷移だからである。

## 1台目完了画面で見せる4つ、その順序

| 順 | 要素 | 心理 |
|---|---|---|
| 1 | **あなたは9人目です** | 承認。自分の2.5時間が形になった |
| 2 | **「もう1台で、あなたの中の比較が出ます」** | **未完了感**。いま手元にあるのは半分だけだと分かる |
| 3 | **次の1台（差分1軸・名指し）** | 具体性。「炭を1個減らすだけ」 |
| 4 | 煙道帳に残った／あとで戻れる | 安心。今すぐ決めなくていい |

**2 が最重要。** 「おすすめだから試して」ではなく **「あなたのデータがまだ半分だから試したくなる」** に変える。
これは外発的動機（推薦）ではなく内発的動機（未完了・好奇心）で、シーシャのように
1回のコストが高い行動には後者の方が効く。

## 時間差の問題（見落としやすい）

1台目の記録は**深夜**であることが多く、2台目は**数日後**になる。
完了画面のモチベーションは、その場では消費されない。

対策（実装コストの小さい順）：
1. **煙道帳のテーマセクションに「次の1台」を常設**（完了画面を離れても同じものが待っている）
2. トップのテーマブロックを、参加者には **「次の1台：#07（炭の数だけ違います）」** に差し替える
3. 通知 → **第一テーマでは採用しない**（§19 未決定。`notifications` は0件で運用実績がない）

## この動線が失敗したときの兆候

**1人あたり METHOD 横断数 1.5 未満（🟡黄信号）＝ M4 の失敗。**
テーマ設計やフレーバー選定ではなく、**まずこの画面を疑う。**

# G. M4「記録後の発見」の具体化

## 出せるもの／出せないもの

| 要素 | 1台目 | 2台目 | 3台目〜 | 条件 |
|---|---|---|---|---|
| 何人目の再現者か | ✅ | ✅ | ✅ | なし |
| 全体平均との差 | ✅ | ✅ | ✅ | **評価者3人以上**のときのみ（既存の `MIN_RATERS_FOR_AVERAGE = 3`） |
| **あなたの中の比較** | ❌ | ✅ | ✅ | 2台以上に味覚入力がある |
| あなたの傾向 | ❌ | ❌ | ✅ | 3台以上。**断定しない** |
| 次の1台 | ✅ | ✅ | ✅ | 未踏の検証対象が残っている |
| まだ誰も試していない METHOD | ❌ | ❌ | ✅ | 検証対象の消化が進んだ後 |

## 「もう1台で比較が生まれる」をどう伝えるか

**禁止**：「もっと記録しましょう」「データにご協力ください」← 労役に見える

**採用**：
```
  いま出せるのは「他の人と比べてどうか」だけです。
  同じテーマでもう1つ作ると、
  「あなたの舌で、どちらが甘かったか」が分かります。
```

ポイントは3つ。
1. **今できないことを明示**する（欠けの可視化）
2. **得られるものが具体的**（「データ」ではなく「どちらが甘かったか」）
3. **他人の評価ではなく自分の評価**が得られると言う（煙道にしかない価値）

## 味覚が入力されていない場合

「あなたの中の比較」は出せない。そのときは**判定（4択）だけで比較を出す**。

```
  #03  おいしかった
  #07  また吸いたい
  → あなたは #07 の方が良かったようです

  味の5軸も残しておくと、次はもっと細かく比較できます。
```

**味覚を必須にしない。** 判定4択でも最低限の比較は成立する。

# H. 投稿を「目的」にしない

## 目指す流れ

```
検証者（他人の作り方を試す）
   ↓  2つ以上作る
比較者（自分の中で比較できる）
   ↓  3台以上・リピートが出る
経験の蓄積（自分のやり方が言語化される）
   ↓  「どれとも違う」と気づく
投稿者（自分の METHOD を登録する）
   ↓
他人に試される → 比較される → データが蓄積
```

## UI に反映されているかの確認項目

| 確認 | 設計上の答え |
|---|---|
| 初回訪問で投稿を促していないか | ✅ テーマページの主導線は「基準の1台を選ぶ」 |
| 1台目完了画面に投稿導線があるか | ✅ **無い**（次の1台のみ） |
| 2台目完了画面に投稿導線があるか | ✅ **無い** |
| 投稿の提案は条件付きか | ✅ 3台以上／どれとも違う／リピートあり、の**いずれか＋1回だけ** |
| 投稿しないと損をする設計になっていないか | ✅ 投稿しなくても比較・傾向・煙道帳はすべて使える |
| 投稿者が優遇されていないか | ✅ 検証対象の採用は運営判断。投稿しても自動で目立たない |
| 指標が投稿を評価していないか | ✅ Primary KPI は**投稿数ではなく2METHOD以上を作った人数** |

## 逆に警戒すること

**METHOD 投稿者数 ＞ 2METHOD以上体験者数** になったら、投稿導線が強すぎる。
その場合は投稿導線を弱め、検証導線（M1〜M4）を作り直す。**METHOD を増やす施策は打たない。**

4. 検証対象は初期8〜12件（恒久的な上限ではない）
5. 1台目から投稿を要求しない
6. 「次の1台」は**1件だけ**提示する
7. **2台目の差分軸は「変更コスト0」の軸（炭の数／初期加熱）から出す**
8. 1台目・2台目の完了画面に投稿導線を置かない
9. 味覚入力を必須にしない（判定4択だけでも比較を出す）
10. 評価者3人未満の METHOD では平均を出さない
11. 個人の比較を一般化した表現にしない（「あなたは〜と感じました」に留める）
12. テーマ用ランキングを作らない
13. Primary KPI は「2METHOD以上を作ったユニークユーザー数」。王道候補は必達にしない
14. 「同じものを擦る」をユーザーに見せない

## 🔬 仮説（検証対象。実装ルールに固定しない）

1. **「差分の名指し」が試行の動機になる** ← 第一テーマの中心仮説

## この UX なら煙道のコア体験が成立する、という設計上の根拠

1. **Primary KPI と主導線が一致している。**
   KPI は「2METHOD以上を作った人数」で、1台目完了画面の主目的が「2台目を作らせること」である。
   計測したいものと、画面が最も強く促すものが同一。

2. **1台目のコストを、既存の行動に重ねている。**
   「投稿してください」ではなく「いつも通り1台作ってください」。
   新しい負担がほぼ発生しないため、参加の意思決定が軽い。

3. **2台目の障壁を、実装ではなくルールで消している。**
   最大の物理的障壁は器材。「変更コスト0の軸から出す」というルール1つで、
   器材所有DBを作らずに障壁を回避している。

4. **報酬が煙道にしか存在しない。**
   「あなたの中の比較」は、同じ人が複数 METHOD を作る構造からしか生まれない。
   他のレシピサイトが模倣できず、かつユーザーにとって実利がある。

5. **「同じものを擦る」を一度も言わずに、同じものを擦らせている。**
   ユーザーの体験は毎回「別の人のやり方を試す」。運営の目的は同一条件の反復検証。
   同じ行動が、両者にとって別の意味を持つ。

6. **失敗したときに、どこを疑えばよいかが決まっている。**
   横断数1.5未満 → M4（記録後の発見）を疑う。
   他人METHOD実施率20%未満 → 投稿導線が強すぎる。
   診断と対処が指標に紐づいている。

7. **必要な新規実装が小さい。**
   新規画面は1つ、DB変更は0。既存の `mix_experiences` / `taste_evaluations` /
   `author_endo_stats` / 熱カーブ比較 / 5軸ピッカーがそのまま使える。
   **戦略の転換に対して、実装の転換がほとんど要らない。**

## 逆に、この設計が成立しない条件

- 検証対象 METHOD の作り手が集まらない（**実装ではなく事業側の課題**）
- 5軸の差が味に反映されない（仮説4が外れる。ただしそれ自体が事業仮説の検証結果）
- 味覚入力の記入率が極端に低く、判定4択だけでは比較が成立しない
