# 煙道 アプリ構造 — フレーバー中心モデル

最終更新: 2026-08-18 ／ ステータス: **実装済み**
関連: `CLAUDE.md`（ルール本体）／ `docs/第一テーマ_設計再構成.md`（体験設計）

> コア機能は **「1つのフレーバーを、いかに美味しく作るか」**。
> フレーバーの組み合わせ（ミックス・配合）という概念は、プロダクトから取り除いた。

---

## 1. なぜ組み合わせをやめたか

同じフレーバーを違うやり方で作り、比べる——これが煙道の中心である。
そこにフレーバーの組み合わせが加わると、変数が増えて**何が味を変えたのか分からなくなる**。

配合が固定されれば、残る変数は作り方だけ：ボウル / 詰め方 / HMD / 立ち上げ時の炭 / 初期加熱。
比較が成立するのは、この5つだけが動くときである。

## 2. 概念とデータの対応

| 概念 | 実体 | 備考 |
|---|---|---|
| **flavor** | `flavors` | 煙道が扱う対象そのもの（86件） |
| **method（作り方）** | `mixes` の1行 | フレーバーは常に1つ。UI表記は「作り方」 |
| **experience** | `mix_experiences` | 作った / 吸った |
| **比較** | `mix_experiences.compared_to_mix_id` / `comparison` / `comparison_axes` | 前に作った別の作り方と比べてどうだったか |
| **taste** | `taste_evaluations` | 味覚5軸（experience 単位） |
| **王道** | `combo_orthodoxy` | **そのフレーバーで**認定された作り方 |

### 効いている構造

作り方に紐づくフレーバーが常に1つになると、**`mixes.combo_key` はそのままフレーバーのキー**
（`brand|name` の小文字）になる。だから組み合わせ用に作った仕組みが、そのままフレーバー用に使える。

```
combo_key            = flavorKey(brand, name)
combo_orthodoxy      = そのフレーバーの王道
theme_progress(key)  = そのフレーバーの段階指標
```

**この改修で DB のスキーマ変更は発生していない。**
`mixes` というテーブル名と `combo_key` という列名は旧モデルの名残で、既存データと
SECURITY DEFINER の RPC がこの名前で動いているため、名前だけそのまま使っている。

## 3. 画面

| 画面 | パス | 役割 |
|---|---|---|
| フレーバー一覧 | `/` | 作り方があるフレーバー → まだ無いフレーバー。今月の検証を最上部に |
| **フレーバー** | `/flavor/[id]` | **中心画面。** このフレーバーをどう作るか。地図・熱カーブ比較・作り方一覧・次の1台 |
| 作り方 | `/method/[id]` | 記録する場所。作った → どうだった → 直接比較 → 味の印象 → 次の1台 |
| 記録の入口 | `/record` | 今日の一台を記録する。次の1台・直近・保存 |
| 登録 | `/post?flavor=<id>` | フレーバー1つ＋作り方。それ以外は任意 |
| 煙道帳 | `/mypage` | 記録の蓄積と、次の1台の常設 |
| 進捗（運営） | `/admin/theme` | L1〜L4 と 比較者/参加者 |

**互換リダイレクト**：`/mix/[id]` → `/method/[id]`、`/mix/[id]/edit` → `/method/[id]/edit`、
`/combo/[slug]` → そのフレーバー、`/theme` → 今月の検証のフレーバー。

## 4. 取り除いたもの

| 取り除いた | 理由 |
|---|---|
| 配合（複数フレーバーと使用量g） | 変数が増えて比較が濁る |
| 「かんたん投稿／詳しく投稿」の2択 | 組み合わせが投稿の主役だった頃の設計。いまは作り方が主役なのでフォームは1つ |
| combo ページ・ComboCard・気分検索のグリッド | 組み合わせという単位が無くなった |
| 「あと1つで作れる」（マイフレーバー） | 1フレーバーでは「作れるか＝在庫があるか」でしかなく、状態が存在しない |
| `getMakeableReps` / `getMyNearMakeable` / `getNearMakeableForKeys` | 上記に伴い参照0件 |
| 作り手向け画面の初心者向け解説（種類の説明・相性の良いボウル・蒸らしの目安） | 実際に作る人には不要。解説は `/hms/[type]` `/bowl/[type]` の役割 |
| ロック（有料ノート）の表示 | `lib/lock.ts` の `LOCK_FEATURE_ENABLED=false`。DBとStripe webhookは残置 |

## 5. 旧データの扱い

編集部見本8件のうち、**複数フレーバーの7件は `hidden=true` で一覧から下げた**（削除していない）。
`combo_key` に ` + ` を含むものがそれで、`isLegacyMultiFlavorKey()` で判定できる。
戻すときは `hidden=false` にするだけ。
